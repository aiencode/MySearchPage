# 搜索入口、屏蔽兼容与光标交接 — 开发 Test Case

## 范围与执行方式

本组保护本对话的修复：搜索入口被“已屏蔽”盖住、共享容器误遮挡头像/历史/收藏、占位继承旧尺寸、Google/必应入口缺失、抖音悬停残留与播放返回入口丢失、跳转关键词丢失与光标错位，以及小红书替换框被侧栏遮挡、原生搜索控件/建议层残留。Git认证/推送不属于产品测试范围。

自动化采用Node内置测试与生产函数、最小DOM/API替身：单进程、64 MB JavaScript堆上限，不安装依赖，不启动浏览器、完整页面、外部进程或网络请求。命令：

```sh
node --max-old-space-size=64 tests/native-search-regression.run.cjs
```

函数提取找不到边界必须报错，不能跳过。DOM替身只提供用例需要的语义，不声称等同于浏览器布局/鼠标事件。自动化成功不等于发布验收完成。

### 公共前置条件（现场验收）

1. 使用专用测试规则；不要覆盖真实规则/历史。局部屏蔽词设为`搜索`、`BLOCKME`，局部URL词设为`/forbidden`。页面标题与当前URL不命中整页规则。
2. 确认扩展实际加载路径、运行版本和后台Service Worker已更新（小红书修复基线1.0.3；抖音播放返回修复1.0.4；必应替换1.0.5；Google首页居中1.0.6或后继版本）。重新加载扩展后，刷新相关源页面；仅刷新网页不证明后台已更新。
3. Google覆盖`google.com`、`google.com.hk`；必应覆盖`www.bing.com`、`cn.bing.com`，输入形态覆盖`input/textarea#sb_form_q`及`[name=q]`；抖音覆盖普通及`/jingxuan/search/`路径。
4. 布局分别在1200px、768px、480px、390px检查。保留头像、历史、收藏和关闭/返回按钮。
5. 自动化默认后台操作，禁止置顶窗口、全局键盘、模拟登录、绕过验证码。真实鼠标定位是人工发布验收；窗口自然获得焦点即可，验证工具不可强制聚焦窗口。
6. 各用例独立恢复测试状态；不保存测试关键词到历史，不提交搜索。默认不播放媒体；TC-NS-19等明确授权的播放返回用例仅打开与关闭必要视频，不做点赞、收藏或发送。临时探针使用完必须卸载，不把诊断面板/脚本打包发布。

## 用例

### TC-NS-01（P0）搜索入口不被局部屏蔽规则盖住
- 前置：页面含命中`搜索`的原生搜索输入与submit，以及替换后的只读入口；页面本身未整页阻断。
- 操作：分别在替换先启动、屏蔽先启动时扫描；对替换入口及其内部节点触发点击匹配。
- 预期：原生搜索输入在替换前受保护；自有入口不成为屏蔽候选/卡片，局部交互匹配返回无阻断；入口可见并能跳转。真正命中的普通按钮仍屏蔽。
- 自动化：`native-search-blocking-regression.test.js`中TC-NS-01；可见与可点击需现场验收。

### TC-NS-02（P0）共享导航外壳不整体替换
- 前置：普通div或`role=button`外壳包含搜索、头像、历史、收藏，只有一个独立控件命中BLOCKME。
- 操作：扫描外壳；向上寻找阻断目标；动态再挂载一组“BLOCKME按钮+收藏按钮”。
- 预期：外壳和搜索入口祖先不能作为单一普通控件屏蔽；命中子控件仍处理；未命中控件保留且点击不因兄弟文字被阻断。语义结果卡片/结果流中的既有整卡屏蔽不因此失效。
- 自动化：TC-NS-02、TC-NS-03（结果卡片反例）；动态布局需现场验收。

### TC-NS-03（P0）保护入口不绕过原有阻断
- 前置：普通按钮含BLOCKME；链接href含/forbidden；已知结果卡片明确命中；另准备整页URL命中场景。
- 操作：对普通按钮/链接、受保护入口分别执行交互匹配；启用整页规则后再次检测入口。
- 预期：普通关键词/URL匹配仍阻断；局部保护不屏蔽整个导航，也不解除整页阻断。整页规则优先于入口局部豁免。
- 自动化：TC-NS-03。

### TC-NS-04（P0）占位按自身内容尺寸收缩
- 前置：命中控件原样式width950px、height280px、min-height200px、padding20px、positionfixed/absolute、z-index9999；分别准备容器和input/img叶子控件。
- 操作：屏蔽并读取占位与CSS；关闭屏蔽/移除规则后恢复。
- 预期：显示“已屏蔽”，不保留旧宽高/flex基准/最小高度/偏移；图层0，搜索入口图层1；叶子占位也紧凑；原节点、文字和属性可恢复。参考简单样例占位小于100×50px，不占旧区域。
- 自动化：TC-NS-04检查实际生成样式声明与替换/恢复节点；像素尺寸、覆盖与命中测试必须现场验收。

### TC-NS-05（P0）Google可见输入优先于隐藏副本
- 前置：同一页面先放可见textarea[name=q]，后放hidden容器内同类型副本；再交换顺序。额外有无关输入。
- 操作：扫描两种顺序；隐藏副本稍后显现时再次扫描。
- 预期：初次只替换渲染中的搜索输入，隐藏副本不能把唯一入口搬走；无关输入不处理。隐藏/aria-hidden/displaynone/visibilityhidden/零尺寸均不作为当前可见入口。
- 自动化：`native-search-surface-regression.test.js` TC-NS-05；“显现后可扫描”属于函数覆盖，最终布局需现场验收。

### TC-NS-06（P1）动态身份属性触发重新识别
- 前置：挂载尚无name的Google输入；抖音挂载尚无search属性的输入。
- 操作：在节点不替换的情况下，依次补name/type/role/placeholder/aria-label/data-e2e，执行真实MutationObserver回调。
- 预期：属性过滤包含这些身份字段；回调将变化节点分支纳入扫描，动态搜索入口最终生成一次。
- 自动化：TC-NS-06检查过滤契约和生产批次计划；浏览器MutationObserver派发及最终DOM需要现场验收，不把静态契约称为完整通过。

### TC-NS-07（P0）抖音悬停与移开不出现combo残留
- 前置：未标识永久portal外壳具有搜索装饰、边框及::before/::after，内部只有替换入口和空挂载点；上级还含关闭/收藏。
- 操作：反复3轮鼠标移入、移出；重复DOM扫描。
- 预期：入口持续可见；专属装饰外壳displaycontents，伪元素不绘制；外壳DOM仍在，父级无关控件不收起；重复扫描无重复样式/重复标记写入。
- 自动化：TC-NS-07调用真实外壳协调函数；CSS伪元素实绘和悬停必须现场鼠标验收。

### TC-NS-08（P0）详情挂载时恢复外壳布局
- 前置：已收起的抖音portal外壳原displayflex及其priority已记录。
- 操作：在同一外壳挂载video/canvas/详情根；随后移除详情；再将整个节点移出入口祖先链。额外模拟页面自身改写display。
- 预期：挂载媒体/详情时解除收起并恢复原display/priority；移除后重新收起；无关交互控件或结构边界不收起；解除时不覆盖站点后写的样式。不删除挂载点、播放器或关闭按钮。
- 自动化：TC-NS-08。

### TC-NS-09（P0）只读框及关键词来源
- 前置：源原生值与URL词不同；原生为空而URL有词；均为空；含空格、中文、emoji、&、#、?。
- 操作：替换并尝试键入；重建原生输入触发二次替换。
- 预期：入口是只读文本输入，不是disabled；原生非空值优先，缺失从URL解码，空时显示“搜索资料”；不trim/截断正常文字；自有控件不被扫描成原生输入再次移除。Enter只跳转，不在原站编辑/提交。
- 自动化：已有`native-search-redirect.test.js`关键词函数/只读契约及TC-NS-09自有输入排除；真实键盘只读验收人工执行。

### TC-NS-10（P0）真实鼠标点击位置完整交接
- 前置：Google“六点半”、抖音“agi架构”。记录源selectionStart/End，不先用代码设置选区。
- 操作：鼠标点击`六点｜半`、`agi｜架构`；另测词首、中间、词末和长词水平滚动后点击；新页不要再点击输入框。
- 预期：各次仅开一个插件导航标签；文字完整；目标选区分别2–2、3–3或源实际选区；可直接在原位置编辑。延迟读取的是控件引用，不是事件结束后为null的currentTarget。
- 自动化：`native-search-caret-handoff.test.js`现有位置和事件时序测试。硬件点击定位、移动端触摸与长词滚动须人工验收；设置选区+DOMclick只能验证链路，不能代替本条鼠标验收。

### TC-NS-11（P0）后台不可丢失关键词/选区
- 前置：真实OPEN_MYSEARCH_PAGE请求含完整searchContext。
- 操作：经过生产handleMessage分支、共享URL构造器及tabs.create，随后目标恢复函数消费片段。
- 预期：创建URL必须带keyword、selectionStart、selectionEnd、selectionDirection；不得退回只有#msp-focus-search；目标值/选区一致；目标路径不变、active保持原设计、openerTabId为来源tab.id；不得自动提交搜索或另开结果标签。
- 自动化：TC-NS-11（新增生产后台分支串联，不能绕过handleMessage）。

### TC-NS-12（P0）后台填入数据不置顶窗口
- 前置：目标页隐藏，或页面可见但document.hasFocus=false；初始化已完成。
- 操作：处理交接；页面之后自然可见/窗口自然聚焦。
- 预期：后台先写入keyword/selection；不调用focus、不清理待完成片段、不产生定位计时循环、不调用windows.update({focused:true})。自然获得焦点后聚焦输入框并清理片段。
- 自动化：已有隐藏/未聚焦/再次聚焦测试及TC-NS-12后台无副作用契约。

### TC-NS-13（P0）初始化与焦点竞争
- 前置：配置/历史/输入增强尚未完成；现有focus监听器会排队设置末尾位置。
- 操作：初始化前收到交接；完成后恢复；恢复计时期间失焦，再自然聚焦；延迟期间用户改词。
- 预期：就绪前不消费数据；就绪后最终选区不是末尾；失焦保留数据；用户后续输入不得被原关键词或旧光标覆盖。
- 自动化：已有初始化、失焦、延迟不覆盖测试。

### TC-NS-14（P1）旧标记、空词与错误输入
- 操作：请求不带searchContext；传空词；选区负数/超长度/NaN；倒序选区；长度超过8192；非字符串词；不可用导航API；tabs.create抛错；未知fragment。
- 预期：旧空白标记兼容；正常词与选区安全规范化；无关片段不修改现有输入；非法context/API失败不创建标签、不伪造opened成功；保持错误响应可追踪。
- 自动化：`mysearch-navigation.test.js`及TC-NS-14后台错误分支/有符号选区测试。

### TC-NS-15（P0）运行中的旧后台与版本错配
- 前置：安装旧版或旧Service Worker仍运行，磁盘源/目标脚本已变更。
- 操作：检查源值及源选区；捕获请求、tabs.onCreated的初始URL；读取真实新页值/选区。重新加载扩展并刷新相关源页面，再用同样数据重测。
- 预期：旧运行时若只创建空focus URL，验收必须失败，不能只凭“新标签打开”判通过。新运行版本须与发布版本匹配；修复后请求、初始URL、目标值/选区一致。版本核对不得硬编码仅允许1.0.2。
- 自动化：TC-NS-11防止代码分支丢参；真实已安装后台版本错配只能发布验收。自然语言用例避免把修改文件等同于已加载实现。

### TC-NS-16（P0）发布包与临时诊断回收
- 操作：检查manifest引用、navigation.html脚本加载顺序，扫描本次临时诊断挂载/文件及生产窗口聚焦调用。
- 预期：共享导航解析器在navigation.js之前加载；所有manifest脚本存在；未保留临时native-search-caret诊断页/脚本、重型浏览器交接测试或预览壳；无本功能主动置顶/原站全局键盘逻辑。
- 自动化：TC-NS-16契约检查。旧ZIP不能算本次交付，打包后仍须检查包内版本与文件。

### TC-NS-17（P0）小红书替换框不落入左侧栏遮挡区
- 前置：顶部原生搜索区使用`.input-box`或稳定搜索owner；线上CSS通过`.input-box[data-v-*]`决定fixed定位、居中transform及响应式宽度，Vue作用域属性的值可为空。左侧栏的图层高于普通内容。
- 操作：记录原搜索区矩形，在1200/768/480/390px宽度下替换；检查搜索框中心及左侧文字位置的命中元素；二次搜索重建owner后再检查。
- 预期：替换根保留搜索owner的class/id/style及全部`data-v-*`样式作用域（包括空值），不复制onclick、其他data属性或弹层状态；复用时删除旧作用域并同步新owner。通用根样式不改成relative或重置宽度、margin、flex。调整对象是`data-msp-native-search-root`及其中的新只读输入，不是原生放大镜/X；侧栏保留，关键词与光标消息不变，其他站点沿用原通用定位。
- 自动化：`native-search-surface-regression.test.js`中TC-NS-17的4项代码回归。先前四档离线样例未包含Vue作用域，因此不能证明线上修复；真实页背景DOM/API记录另列于执行记录，不能替代四档现场与硬件鼠标验收。

### TC-NS-18（P0）小红书原生控件及返回旧页的建议层清除
- 前置：插件替换框已挂载；头部原生`.input-button`（放大镜/清空控件）、`.min-width-search-icon`及原生建议层`.sug-pad`可能在首次扫描或延迟更新时出现。
- 操作：点击新框任意光标位置并跳转导航页；主动返回来源页；分别检查visibilitychange、pageshow、窗口自然focus后的迟到建议层。停用运行时后检查监听器移除。
- 预期：CSS先防闪现，DOM清理移除原生控件与`.sug-pad`；返回事件再次清理，MutationObserver处理迟到挂载。不得删除新框、其祖先或侧栏；pointerdown/mousedown/focus守卫阻止原生传播但不preventDefault，保留浏览器光标定位和既有关键词/选区交接。停用后解除新增监听器。
- 自动化：TC-NS-18的2项生产运行时回归，覆盖清理对象、返回事件、默认光标动作和监听器注销。真实页DOMclick是合成点击；派发事件与浏览器实际标签返回的证据必须分开记录。已验证真实visibilitychange返回；硬件鼠标定位和人工窗口聚焦仍不由后台探针代替。

### TC-NS-19（P0）抖音关闭站内视频播放界面后搜索框恢复
- 前置：在抖音关键词搜索结果列表中已有插件只读新框；点视频进入同一页面的播放层。搜索结果列表与播放层各自可能保留/重建搜索区，关闭不一定重新生成原生input。
- 操作：播放层关闭分别覆盖卸载DOM、仅hidden/displaynone；返回时原列表头部不重建input、清空子节点或整个头部重建。加入隐藏的原生搜索副本，连续开关3轮，再停用运行时。
- 预期：隐藏搜索区域不能抢走可见入口；播放层卸载或隐藏后，即使没有新原生input，也把同一个新框恢复到此前记录的可见搜索挂载点，保留关键词、选区及跳转监听器。只隐藏列表时不强行展示；原区域整体卸载后不凭空挂到body。新owner出现时复用脱离DOM的原框，不重复入口，不覆盖关闭/返回、结果列表或媒体节点。
- 边界：扩展CSS会预先隐藏原生input，故检测owner/父区域的可见祖先，不能凭原生input零尺寸跳过初次替换；display:contents区域可以作为恢复挂载点。恢复后的重复观察回调不反复搬动/写样式；停用时恢复各仍连接搜索owner并清除注释锚点。
- 自动化：`native-search-surface-regression.test.js`中TC-NS-19的9项定向回归，调用生产createController和观察器回调，仍属小DOM替身，不等同于线上React播放流程验收。真实现场需已授权现有浏览器后台打开视频再关闭核对，禁止独立测试浏览器或前台聚焦兜底。

### TC-NS-20（P0）必应搜索框替换及关键词交接
- 前置：扩展1.0.5或后继版本，必应不需加入高风险域名名单；页面未被整页屏蔽。覆盖国际版、国内版及首页/结果页的input、textarea形态。
