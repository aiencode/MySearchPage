# 站点搜索入口：关键词与光标交接

## 现行行为

- “搜索资料”入口为只读文本输入框，展示原生关键词；原生值为空时，从站点搜索 URL 恢复。
- 点击后沿现有 `OPEN_MYSEARCH_PAGE` 链路打开插件导航页新标签，不在原站编辑、不自动提交搜索。
- 传递完整关键词与浏览器 UTF-16 选区。点击定位完成后再采集选区，异步回调保留控件引用，不读取失效的 `event.currentTarget`。
- 导航页初始化完成后填入文字并设置选区。这两项不依赖页面可见或窗口焦点；隐藏/未聚焦页也接收数据，不主动聚焦。
- 页面自然可见、窗口已获焦点时完成输入框聚焦和交接标记清理。旧空白聚焦标记仍兼容。
- 保留现有目标页和新标签创建关系，不调用 `chrome.windows.update({focused:true})`。
- 扩展版本更新为 `1.0.2`。

## 轻量回归

单进程、无浏览器/jsdom/整页启动、64 MB JavaScript 堆上限：

```sh
node --max-old-space-size=64 -e "require('./tests/native-search-caret-handoff.test.js');require('./tests/mysearch-navigation.test.js');require('./tests/native-search-integration.test.js');"
```

20 项通过，包括开始/中间/末尾位置、中文与特殊字符、UTF-16 选区、点击时序、初始化时序、后台填入不调用聚焦、延迟恢复不覆盖后续编辑、URL/消息链路及新标签创建参数。

## 已安装扩展的现场验证

用户明确授权当前已有 Chrome 配置后，确认扩展加载目录为本仓库 `extension/`。未启动独立浏览器进程或复制用户资料。

失败证据：源框有 `agi架构`、位置 3；诊断向真实后台发送这些数据后，后台实际创建 URL 只有 `#msp-focus-search`，没有关键词/选区参数，目标页为文字空、位置 0。源脚本和导航页解析器均已更新，运行中的后台仍表现为旧空白跳转实现。

重新加载本扩展、刷新相关源页面后，实际运行版本确认是 `1.0.2`，创建 URL 开始带完整关键词和选区。未重新启动 Chrome 或 PI。

随后使用后台 DOM 点击验证**原源控件监听器 → 真实后台 → 真实新标签输入框**，不是模拟后台：

| 来源 | 源关键词与选区 | 实际新页文字与选区 | 结果 |
| --- | --- | --- | --- |
| Google | `六点半`，2–2 | `六点半`，2–2 | 通过 |
| 抖音 | `agi架构`，3–3 | `agi架构`，3–3 | 通过 |

两次后台 DOM/API验证的窗口焦点前后状态相同（均为 true），没有调用窗口聚焦 API。该记录证明未改变窗口焦点状态，不表述为测试时窗口本身已经处于后台。

## 方法与限制

- 后台源控件测试通过 `chrome.scripting` 在限定的已授权源标签设置选区并触发 DOM 点击；真实扩展生成新标签，随后直接读取新页 `value`、`selectionStart`、`selectionEnd`。
- 这不是硬件鼠标坐标验收。内置预览中的真实鼠标验证只证明基本选区采集；外部驱动的可信指针尝试没有产生可确认的新标签，未计为通过。
- 前面的独立浏览器扩展测试曾伴随用户报告的死机/应用退出，未认定原因，未认定那套端到端测试通过。相应重型脚本已移除。
- 临时诊断页、面板、挂载脚本和预览文件已回收；实际页面上的自检面板/URL标记已清除。验证 JSON 与日志仅保存在本轮 scratch。
- 后续默认后台操作，不再以窗口置顶或前台全局按键作为验证方式。
