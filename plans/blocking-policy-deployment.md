# 阻断策略部署与验证

## 策略格式

`extension/policies/blocking-policy.template.json` 是版本 1 模板。三个集合相互独立：

- `blockedKeywords`
- `blockedUrlPatterns`
- `highRiskDomains`

设置页“追加导入策略”只做去重追加，不删除已有值。四站导航深度控制只有在对应域名存在于 `highRiskDomains` 时启用。

## 部署

1. 运行仓库测试、语法检查和 JSON 检查。
2. 在浏览器扩展管理页重新加载现有 MySearchPage 扩展。
3. 在设置页追加导入审核后的策略文件。
4. 扩展自动重新连接已打开的四站标签；也可点击“重连旧标签”。
5. 使用“线上兼容诊断”读取用户已打开且有权访问的四站页面。

不得把本地测试、离线 fixture 或诊断页成功打开描述成线上四站验证通过。

## 旧版本迁移边界

本版本开始把扩展写入的行内样式和媒体状态记录到 DOM 账本，重载后新内容脚本可以安全撤销仍由扩展持有的值。

升级前已由旧版本修改、且旧隔离世界已经失效的标签没有该账本，无法可靠推导原站行内值。首次升级时这些历史孤儿页面可能仍需用户手动重建一次；代码不会自动刷新或替换用户页面。

## Codex 自动化边界

Codex 可以原样应用补丁并运行 Node 测试、语法检查、Manifest JSON 检查和 `git diff --check`。策略导入、扩展重新加载、登录态页面取证及正式发布需要用户授权的浏览器环境；命令通过不能替代部署确认。
