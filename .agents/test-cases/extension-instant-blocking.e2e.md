# 即时阻断与旧标签回收 Test Case

## 来源与目标

- 用户要求保留原有屏蔽规则，彻底清除图片刺激及配套等待设计，只进行即时阻断；不保留旧实现备份。
- 用户继续反馈“图片换了但仍有延时”。真实 Chromium 离线复现发现：当前违规页会连带拦截正常导航；成功 history 操作缺少状态更新通知；删除前后沿用同一运行标记，旧标签被误判为新版。
- 目标版本基线：扩展 **1.0.7**，阻断运行标记 **immediate-rule-blocking-v4**。后续版本应核对发布版本与前后台标记一致，不能永久依赖本条版本号。
- 正式验收以本文为准；[自动化映射](../../tests/extension-instant-blocking.mapping.md)说明现有覆盖与缺口；[消融记录](../../plans/instant-blocking-ablation.md)仅承载历史实验结果，不替代验收。

## 通用前提与判定

1. 使用专用测试配置；线上复核须有相应浏览器访问授权。记录浏览器、扩展实际运行版本、加载目录、运行标记、测试网址、命中规则及开关状态。磁盘 manifest 已修改不代表旧页面已更新。
2. 测试词使用无害且唯一的 `BLOCKME` 或 `REPRO_BLOCKED`；普通对照使用 `safe`。匹配保持字面包含和既有优先级，不增加语义识别。不得删除规则或关闭功能来证明“没有阻断副作用”。
3. “即时”指取消默认动作和阻止事件传播在当前调用返回前完成，且不等待统计存储、计时器或固定冷却期；正常动作无需等倒计时结束。不要用一个固定毫秒阈值代替此因果判据。
4. 禁止反馈图片/备用图、提示音、闪屏、惩罚倒计时和等待解锁。当前违规内容仍可被既有卡片占位或页面状态阻断，常驻说明不等于反馈弹层；不得借当前违规状态阻止导航至未命中规则的有效目标。
5. 路由恢复必须通过真实 MAIN 世界 history 钩子和实际扩展执行。不得人为补发 popstate、刷新页面、重载扩展、篡改门禁或调用原始 history 来让正常路由用例通过。
6. 验证动作是否真的被取消、目标 URL 是否改变、正常按钮是否可见且真实点击生效；仅查 DOM 属性、仅有按钮节点或仅统计消息成功，不足以证明用户可操作。
7. 不读取或复制用户 Cookie、账号配置和私钥；不创建旧源码/资源副本。临时浏览器配置退出后清理；保留结果和必要截图，不以保留旧实现做对照。
8. 每次运行分别记录“通过 / 失败 / 环境阻塞 / 未执行”。离线 DOM、真实浏览器离线页和真实站点分别报告，不把历史 224 项通过当作本轮重跑。

## IB-01：关键词、URL 和作者规则仍然阻断

**ID：TC-INSTANT-BLOCK-001**

- 前提：专用配置分别设置关键词、URL、作者规则；准备仅命中一种规则的卡片或入口及未命中对照。
- 步骤：逐类尝试进入命中内容，覆盖鼠标及可用的键盘激活；再操作相邻普通内容。检查命中卡片、页面根和导航目标。
- 期望：命中动作被取消，原始违规入口不可继续访问；保留既有局部占位/阻断记录，普通内容仍可操作，不增加刺激图或等待。规则仅影响命中范围，不替换整个应用根。
- 失败判据：为移除反馈而放行违规内容、错误删掉规则、整页无关内容被替换、作者判定变成整页文字匹配、普通对照也被拦截。
- 证据：逐类记录规则、动作结果和实际目标。通用 blockEvent 的三类 match 测试只证明处理已知匹配，不等于三类匹配与真实 UI 全链路均验收。

## IB-02：阻断不附带图片、声音、闪屏或等待

**ID：TC-INSTANT-BLOCK-002**

- 前提：阻断开启，命中局部入口或页面规则；可观察扩展 DOM、资源请求、音频调用、计时任务及统计消息。
- 步骤：触发阻断，立即检查页面；在同一事件返回后尝试允许动作；检查是否安排等待解锁或产生废弃效果事件。
- 期望：阻断同步生效；无图片/备用 SVG、提示音、闪屏、临时反馈弹层、倒计时及延时恢复；有效阻断记录可异步发送，但不延后事件取消。
- 失败判据：原图删除后出现替代图、等待数秒才恢复、效果事件仍发送、换成另一种刺激表现或仅隐藏资源而保留执行代码。
- 证据：取消顺序、节点/请求、音频调用及计时用途。不能用“没有 setTimeout”要求删除无关页面功能，也不能把普通网络响应超时自动等同惩罚倒计时。

## IB-03：重复尝试与统计慢响应不改变即时阻断

**ID：TC-INSTANT-BLOCK-003**

- 前提：可模拟统计请求未完成、重复记录被去重；规则保持开启。
- 步骤：在去重窗口内连续三次尝试同一违规动作；同时操作未命中入口。对照统计存储一直 pending 的情况。
- 期望：每一次违规动作均当场取消；去重仅减少记录次数，不产生冷却期、不放行后续尝试、不锁住普通动作；存储完成与否不影响取消。
- 失败判据：只挡第一次、等待存储/倒计时、去重后放行或重复出现反馈界面。

## IB-04：四站搜索词使用同一阻断规则

**ID：TC-INSTANT-BLOCK-004**

- 前提：哔哩哔哩、抖音、YouTube、小红书分别有命中和普通搜索；准备编码词、搜索 URL、可用原生提交及导航入口。
- 步骤：检查搜索提交、直接搜索 URL 和 MySearchPage 搜索打开路径；覆盖桌面/移动或旧路由别名、URL 编码及空搜索。对照详情 URL 中同名参数、伪装域名和非法 URL。
- 期望：四站有效搜索词同按字面规则判定，前后台结果一致；B 站 search 子域名与抖音 jingxuan 搜索不漏判；详情参数、未知域名不冒充搜索词；没有新增等待。
- 失败判据：只支持 YouTube、前后台编码判定不一致、普通搜索被拒绝、空搜索异常或详情被误当整页搜索。
- 证据：分站/分入口记录。四站离线搜索页通过不能证明线上全部搜索表单可用。

## IB-05：正常 SPA 路由可立即离开被阻断页面

**ID：TC-INSTANT-BLOCK-005**

- 前提：四站各进入命中搜索词的页面，页面级阻断已建立；普通目标自身不命中任何规则，标题等其他字段也无命中。
- 步骤：经产品 MAIN 世界钩子执行正常 pushState，再执行正常 replaceState；每次返回后立即检查当前地址、门禁和普通按钮，并真实点击普通按钮。
- 期望：路由提交成功即同步重算并解除旧门禁；普通控件可见、可点击；每次成功操作仅有一次路由提交通知，不等待 DOM 变化或冷却期。
- 失败判据：当前页面违规导致所有正常目标都被拦、地址变化后遮挡不退、必须补发 popstate/刷新才能点击、只测合成事件而真实点击失败。

## IB-06：恢复后再次进入违规路由仍被拒绝

**ID：TC-INSTANT-BLOCK-006**

- 前提：完成 IB-05，当前正常搜索及普通按钮可用。
- 步骤：从该正常页面用 replaceState 再次请求命中词目标；检查 URL、门禁、提交通知次数及普通按钮。
- 期望：违规目标被取消，URL 和当前正常页面不被改变；被拒绝操作不发路由提交通知，正常按钮继续可用，无图片或等待。
- 失败判据：修复“能离开”后变成所有路由放行、违规操作改变当前页、无成功提交却发送通知、反向把正常页锁住。

## IB-07：页面规则和未命中边界保持有效

**ID：TC-INSTANT-BLOCK-007**

- 前提：分别准备当前 URL 命中、标题命中、禁止主页、普通详情和未命中按钮；主页权限与内容总开关分别记录。
- 步骤：逐项触发页面级规则；对照普通详情、关闭内容阻断、同页普通表单，以及普通表单嵌套在搜索容器内的情况。
- 期望：各规则保持既有职责；页面命中仍阻止违规访问/播放，正常详情和无关表单不被搜索框借值误拦；内容开关不覆盖独立主页权限；无反馈/等待。
- 失败判据：移除表现层同时撤销页面规则、关闭内容规则误放开禁止主页、无关表单借用别处搜索框值而被取消。
- 证据：独立规则判定与最终动作分开记录；用例没有要求停用现有主页网络阻断策略。

## IB-08：显式重连回收所有网站的旧阻断标记

**ID：TC-INSTANT-BLOCK-008**

- 前提：专用浏览器打开一个旧标记四站页、一个旧标记 Google 页和一个当前标记 Google 页；记录当前页实例标识。只在测试页构造旧标记，不引入旧代码备份。
- 步骤：通过设置页真实发送“重连旧标签”请求；记录处理/刷新数；等待刷新完成并从页面读取运行标记。
- 期望：两个旧标记页面刷新并实际运行当前版本；当前 Google 页面实例不变；非四站不注入搜索媒体脚本。显式操作不局限四站，自动启动接管仍保留四站边界。
- 失败判据：旧、新版本共用标记而刷新为 0、漏掉 Google 等站、只返回成功但页面仍旧版本、所有新页面也被刷新或媒体规则扩大到非四站。
- 证据边界：人工设置旧标记验证版本回收分支，不证明历史旧脚本及其内存资源已被完整复现；自动启动范围、媒体未注入需独立观察。

## IB-09：资源、发布清单与运行身份无废弃实现

**ID：TC-INSTANT-BLOCK-009**

- 前提：检查当前发布源码、manifest、分发产物及运行中的扩展。
- 步骤：核对加载目录、扩展版本和前后台标记；检查图片目录、备用图、效果函数/接口、资源公开授权、旧功能开关和过期安装包。
- 期望：仅保留即时阻断，旧表现实现、资源与备用入口已移除，无源码/资源备份；实际加载版本与发布目标一致。测试中用于拒绝回归的标识不当作运行实现。
- 失败判据：只删图片文件却保留回退图、旧分发包仍可启动旧设计、磁盘是新版本但运行旧脚本、假报当前用户浏览器已更新。
- 证据：磁盘检查与浏览器实际身份分别报告。不能因新临时浏览器通过而替用户原有配置签收。

## IB-10：统计数据库升级仅清除废弃数据

**ID：TC-INSTANT-BLOCK-010**

- 前提：专用旧版数据库中含有效曝光/点击记录、废弃效果事件和有效记录上的旧效果字段；屏蔽规则及主页设置已有值。
- 步骤：由新版统计接口首次打开数据库并升级；查询保存结果，再重开检查；对照有效阻断记录继续写入。
- 期望：废弃事件被删除，旧字段移除；有效记录、规则、设置不丢失，旧事件类型不再接收；迁移不阻塞即时取消动作。
- 失败判据：清空全部历史或规则、残留废弃字段、升级不完成、新记录无法保存，或需等待迁移才取消访问。
- 证据：fake-indexeddb 的统计库迁移不等于真实 Chrome 原用户数据库已完成升级；规则存储与重开持久化需分别验证。

## IB-11：设置页删除效果表后仍可操作

**ID：TC-INSTANT-BLOCK-011**

- 前提：新版设置页，规则列表及阻断统计有数据；桌面、≤768px、≤480px 三档视口。
- 步骤：打开设置，读取规则与统计，操作保留的规则编辑和刷新；检查是否依赖已删除表格才能初始化，检查三档布局。
- 期望：不显示效果实验表；规则编辑器和有效阻断统计正常初始化、操作与保存；无废弃 DOM 依赖或空占位，沿用既有响应式间距。
- 失败判据：删表后脚本提前返回、规则无法编辑、刷新异常、残留效果行或移动端错位。
- 证据：现有 jsdom 用例只证明规则/三行统计可渲染，编辑保存与三档视觉验收不得据此自动记为通过。

## IB-12：用户现有浏览器升级后的实际体验

**ID：TC-INSTANT-BLOCK-012**

- 前提：用户已授权的原浏览器，原来出现图片/倒计时的相关页面，规则保持原值；需能读取运行身份及实际故障现场。
- 步骤：确认原加载目录和版本；重载新版扩展，按需显式重连旧标签；重新执行原违规尝试及正常退出/搜索，在原页面观察图片、声音和等待，再确认规则仍拦截。
- 期望：实际页面运行当前脚本，原图片/倒计时消失，普通动作无需等待，匹配目标仍不能访问；不改用户登录状态和无关规则。
- 失败判据：仅启动独立配置就宣称原配置修好、旧脚本仍驻留、靠清规则通过、只提供磁盘版本而没有实际页面证据。
- 状态：**原有 Chrome 配置的端到端验收未完成**；历史页面读取受宿主会话接口拒绝。独立可见 1.0.7 的启动和脚本身份核对是另一份证据，不能替代本用例。

## 执行记录与回归纪律

每次发布记录用例 ID、场景输入、实际加载身份、步骤、实际结果、日志/截图及限制。当前自动化结果和历史消融见映射文档；本次仅更新文档，没有重跑产品测试。无法读取页面、网络失败、登录挑战或工具拒绝均记为环境阻塞，不算通过。修复重测不得只改测试期望，也不得用新增延时、替代图或放开规则掩盖故障。
