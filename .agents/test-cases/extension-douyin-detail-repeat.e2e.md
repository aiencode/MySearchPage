# 抖音搜索详情连续打开/关闭回归 Test Case

## 来源与目标

- 来源：本会话用户反馈“问题未解决”，实际故障为打开视频 → 点左上角 × 关闭 → 再点结果，只有声音而没有详情画面，后续点击失效；用户要求防止该修复回归。
- 已取证的根因：搜索入口替换把暂时只有搜索控件的无标识祖先脱离文档。抖音下一次仍向该缓存节点挂载详情；该节点移除时没有媒体，之后才出现详情和媒体。因此测试必须覆盖**播放器尚未存在时的容器保护**，不能只保护已有视频。
- 目标：在不刷新、不重新加载扩展、不改变用户规则的连续操作中，每次结果进入对应详情，画面可见、可以播放；点 × 后恢复搜索列表，下一次点击有效。

## 通用前提与证据

1. 真实线上验收使用已获授权的浏览器配置和开发版扩展。记录浏览器/扩展版本、搜索地址、媒体开关、结果实际目标 ID；不改变登录状态或无关设置。
2. 搜索词可用 JavaScript，但不得依赖固定排序、标题或视频 ID。选择至少三个可访问的视频，四轮中包含不同结果及重复打开同一结果。每次点击前重新确认目标，避免列表重排造成点错。
3. 除用例明确指定的初次打开外，所有轮次连续执行，不能用刷新、导航到干净地址、重载扩展或 Esc 替代 × 来恢复故障。需要恢复才能继续即该轮失败。
4. 打开成功必须同时有：对应详情可见、媒体节点连接到当前文档、有效画面尺寸、正常播放状态/播放时间推进。URL 有 `modal_id`、声音出现、DOM 中存在隐藏缓存详情、仅第一次成功，均不足以通过。
5. 关闭成功必须有：详情不再遮挡列表、结果入口可操作、页面滚动锁按原站行为解除、详情播放停止；下一次打开不受旧详情或空壳遮挡。旧详情内容不能冒充新目标。
6. 记录每轮目标、详情画面、播放状态/时间、关闭后的地址/滚动状态及失败现场。自动化模拟 MediaStream 不证明实际扬声器输出；真实音轨按原站可用条件核验，不突破登录/付费/地域限制。
7. 离线代表 DOM、单元测试与真实抖音分别报告，不能将本地通过写成线上全部结构兼容。服务错误、验证挑战或原站视频不可用记为环境阻塞，不记为通过。

## DYP-01：媒体隐藏关闭，连续四轮点 × 关闭与再次打开

**ID：TC-DY-DETAIL-REPEAT-001**

- 前提：抖音媒体隐藏关闭；搜索结果可正常打开详情；扩展的搜索入口替换生效。
- 步骤：从结果打开 A 并观看；用详情左上角 × 关闭；依次打开 B、C、A，每次确认画面/播放后用 × 关闭，连续四轮，不刷新或重载。
- 期望：四次详情均正常显示、允许观看；目标与本轮实际点击一致；四次关闭均返回原搜索环境，列表文字与入口保留，下一次点击有效。
- 失败判据：有声无画面、地址已带详情 ID 但仍显示列表、视频挂在脱离文档的节点里、点击无响应、旧详情挡住列表、需要刷新才能打开任一后续详情。

## DYP-02：关闭后重建搜索控件，播放器延迟挂载到同一空容器

**ID：TC-DY-DETAIL-REPEAT-002**

- 前提：开发代表页面保存搜索外层容器的对象引用；该无标识容器初始及关闭重建时只有搜索输入/提交控件，没有 video/canvas/关闭按钮；下一次详情异步挂载到该同一对象。
- 步骤：加载产品搜索替换脚本；等待搜索输入被替换；点击结果挂载详情；点 × 移除详情并重建搜索控件；等待扩展处理完，下一次点击再延迟挂载详情，至少四轮。
- 期望：首次替换及每次关闭处理后，保存的外层容器身份不变且 `isConnected=true`；每次详情/视频都能从当前 document 查到，而非只存在于保存的脱离节点中；原结果节点身份不变。
- 失败判据：只在视频出现后才保护、重新创建一个同名容器伪装保留原节点、空容器被替换、只断言对象里有视频而不检查 document 连接。

## DYP-03：多层无标识包装及误导性的搜索 class

**ID：TC-DY-DETAIL-REPEAT-003**

- 前提：输入/提交的直接搜索区域外有三层无标识包装；其中 class 可含 `search-shell` 或 `search-wrapper`，但没有明确搜索 owner 标识。外层将用于挂载详情。
- 步骤：在首屏及关闭重建后处理搜索入口；再挂载详情并连续开关四轮。
- 期望：不能仅凭 class 中的 search 或“没有无关控件”提升替换范围；所有无标识包装身份及连接保留，后续详情可见并播放。
- 失败判据：任意中间层被整层替换导致 portal 脱离，或只保护第一层/首屏而在动态重建后失效。

## DYP-04：明确搜索区域仍可替换，不能靠禁用功能过关

**ID：TC-DY-DETAIL-REPEAT-004**

- 前提：安全搜索区域有 `data-e2e="searchbar-container"` 等产品现行明确 owner 标识，只包裹搜索控件；外围无标识节点仍为未来详情挂载点。
- 步骤：处理搜索区域，随后用外围挂载点打开详情；并以包含关闭/无关控件的共享区域作边界对照。
- 期望：明确、安全的搜索 shell 可以成为替换目标；原生输入被处理，自绘入口唯一且可用；外围及无关关闭控件不被删除。不是全局停止替换，也不是停止 MutationObserver。
- 失败判据：完全禁用搜索替换来通过容器保留、只移除功能断言、整个带关闭控件的共享外壳被吞掉。

## DYP-05：移除详情和缓存隐藏详情两种关闭路径

**ID：TC-DY-DETAIL-REPEAT-005**

- 前提：开发代表页面分别支持 × 关闭后移除详情，以及隐藏缓存详情并在下次重用；关闭路径均重建原生搜索控件。
- 步骤：每种路径连续四轮真实点击结果/×；覆盖不同目标和重新打开先前目标；每次关闭后等待搜索处理，再打开。
- 期望：两种路径均正常显示本轮内容/播放，× 清除滚动锁；缓存不能继续播放、遮挡或成为唯一仍存活的脱离 portal；自绘搜索入口始终唯一。
- 失败判据：只支持彻底销毁、不支持隐藏缓存；关闭后旧视频继续播放；重开还显示上一次内容；入口重复或列表被替换。

## DYP-06：媒体隐藏开启，已有封面复用为详情祖先

**ID：TC-DY-DETAIL-REPEAT-006**

- 前提：抖音媒体隐藏开启；代表/真实结构支持复用被隐藏的封面容器作为详情祖先，背景结果依然存在。
- 步骤：通过保留的文字入口连续打开/关闭四轮，覆盖缓存隐藏和移除重挂载；打开时查看详情与背景结果，关闭后检查空封面和下次入口。
- 期望：详情祖先撤销扩展持有的隐藏/收起覆盖，保留原站尺寸和定位，详情允许播放；背景媒体仍按开关隐藏/暂停；关闭后收起空壳，不拦截下一次点击，不强行改写原站 hidden 状态。
- 失败判据：仅修复隐藏关闭路径；详情继承隐藏祖先、尺寸为零或被静音/暂停；背景全部放行；缓存标题/按钮留下阻挡点击的空封面。
