# 搜索结果媒体隐藏 E2E 测试用例

## 权威需求与来源

- 来源 A：用户分享的需求，<https://chatgpt.com/share/6a942ba9-4034-83e8-8c12-24939f216a76>。本轮仅采用主任务传入并确认属于当前范围的要求；不把分享内容中的其他能力纳入本文件。
- 来源 B：当前主会话中用户明确确认：“收起图片区域，保留原有文字与入口”。
- 来源 C：当前主会话中用户明确确认：“正常显示，允许观看；只屏蔽结果卡片的预览”。
- 来源 D：主任务传入的本轮已确认范围：四站结果图片、封面、头像、预览隐藏并塌缩；文字与真实入口保留；暂停预览且无声音；动态加载与搜索路由；详情页及弹窗隔离；返回搜索继续作用；局部处理且无额外补结果请求。
- 来源 E：主任务确认的能力隔离要求：媒体启用时不受 UA 总开关、单站 UA enabled 或 uiTransform 状态影响；媒体处理不改变 UA 配置，也不触发 UA 标签页 reload。
- 来源 F：当前主会话中用户明确确认：“四站默认开启，可按站关闭（推荐）”。
- 来源 G：主任务确认的设置方案：在现有 options 页面提供独立的四站媒体设置区域，可访问标题为“搜索结果图片与预览”，四开关标签为“哔哩哔哩”“抖音”“YouTube”“小红书”；按站关闭后恢复该站搜索媒体和布局，重新开启继续处理已有及动态结果；设置保存后重开仍保持；设置变化即时应用，不刷新当前详情，不改变 UA 配置或现有 UA 区行为。
- 技术来源（主任务提供，未读取实现）：媒体配置使用独立的 `searchMediaSettings`，值为四基础域名到布尔值的映射；通过 `chrome.storage.local` 保存并由 `chrome.storage.onChanged` 应用变化。以下 TC 不要求 UI 呈现这些内部名称，也不把媒体默认字段并入 UA 配置。

## 共用前提与判据

- S-01～S-13 以“本功能对当前被测站点处于生效状态”为前提；S-14～S-18 分别按其前提覆盖默认、关闭、重新开启和持久化行为。设置入口位于现有 options 页的独立四站媒体区域。
- 小红书、YouTube、抖音、哔哩哔哩分别执行适用场景，不能用一个站点通过代替其他站点。详情页与弹窗按各站实际支持的入口形式覆盖，不要求站点提供原本没有的交互。
- 为每站选择可复现的结果与可访问的详情内容，记录原生对照：结果文字、访问目标、媒体独占区域以及原生加载操作。对照内容须相同，避免把结果随机排序或登录权限差异判为功能变化。
- “收起”指媒体独占的宽高、占位和留白不再挤占布局。仅透明、遮挡或隐藏图片内容，而保留其封面框、固定高度或比例占位，不满足要求。文字本身所需的空间不算媒体空白。
- 隐藏与收起分别判定。收起必须用真实浏览器中的元素矩形、相邻内容位置和最终布局检验，覆盖固定高度、`aspect-ratio` 封面容器及瀑布流定位留下的空白；仅断言图片的 `display: none` 不能证明收起。为保留原文和原链接而调整现有容器布局，符合收起要求。
- 本地结构 fixture 通过仅证明给定结构及交互条件下的行为，不能替代小红书、YouTube、抖音、哔哩哔哩真实页面在浏览器中的通过证据。只有真实四站样本覆盖后才可报告四站在线兼容性；证据报告应明确区分这两种覆盖范围。
- 预览样本应包含能实际自动播放且带可听音轨的内容，并同时观察播放状态与音轨输出。单凭截图没有画面或扬声器没有声音，不能证明预览已暂停；静音但继续播放也不满足 R-04。
- 详情播放与站点原生对照一致：允许用户按站点正常方式点击播放、取消静音和观看；不要求突破登录、付费或地域限制，也不规定站点原本没有的自动播放行为。

## 当前有效 TC

### S-01：四站首屏结果图片和封面收起

**ID：TC-01a07543-5a84-7268-83ed-ebe9a540e9be**

- 需求位置：R-01、R-02、R-03；来源 B、D。
- 前提：当前站点已有含图片或视频封面的搜索结果原生对照，功能生效。
- 输入/步骤：打开该站搜索结果页；等待首屏原生结果完成呈现；观察含媒体和文字的各类结果卡片。
- 期望：结果图片和封面不显示，媒体独占区域收起；结果原有文字和访问入口保留。
- 判据：与同内容对照比较，图片、封面及其空白占位均消失；分别验证媒体不可见和布局矩形确已收起。固定高度或比例容器不能留下原尺寸，瀑布流相邻卡片定位不能继续保留被移除媒体造成的空白；不能通过隐藏整张卡片、截断文字或删除结果来满足要求。分别记录四站的覆盖归属。

### S-02：头像、多图与混合内容边界

**ID：TC-01a07543-5a85-7349-9126-28434946fe97**

- 需求位置：R-02、R-03；来源 B、D。
- 前提：搜索结果中包含作者或用户头像，且有多图或文字与图片混排的可复现样本。
- 输入/步骤：查看上述结果；观察头像、首图、其他图片及相邻的作者名、标题、摘要、统计文字和按钮。
- 期望：结果内所有图片和头像均收起；相邻文字及入口保持可见、可用。
- 判据：不能只处理第一张图、只处理视频封面、把结果头像列为例外，或因隐藏共同父区域而连带删除作者名及入口。站点实际采用不同媒体呈现方式时均适用同一判据。

### S-03：原有文字和真实入口可用

**ID：TC-01a07543-5a86-7205-a273-4892fe4902aa**

- 需求位置：R-03、R-06；来源 B、C、D。
- 前提：存在原本带标题、作者链接或其他文字入口的结果；已记录各入口原生目标和正常支持的操作。
- 输入/步骤：在媒体收起后阅读原有文字；分别通过鼠标及原本支持的键盘方式激活这些入口；对原生支持新标签打开的链接使用该操作。
- 期望：原有文字没有被替换或遗漏，原有可访问入口仍可操作，并通向同一内容或作者目标。
- 判据：没有遮罩或隐藏容器拦截点击和焦点；不能用空链接、其他目标或新增中转页代替原入口。无文字且封面为唯一入口的结果按 D-02 保留为待决样本。

### S-04：自动预览暂停且无声音

**ID：TC-01a07543-5a87-7de0-b7e4-acd3a543f0b1**

- 需求位置：R-02、R-04、R-05；来源 C、D。
- 前提：搜索结果样本在原生页面会因进入视口、悬停或其他站点现有动作触发带音轨的自动预览。
- 输入/步骤：打开结果页；依次触发站点原有自动预览条件；移出再移入视口或重复悬停；覆盖延迟加入、开始自动播放的结果预览。
- 期望：结果预览画面不显示，其区域收起；播放不启动或已被暂停，没有预览声音；重复触发不恢复播放。
- 判据：同时检查预览播放状态与音轨输出。仅隐藏画面仍继续有声、仅静音仍持续播放、再次悬停恢复预览，均不满足预期。本用例不把用户主动打开的详情播放当成结果自动预览。

### S-05：后续加载、延迟更新和重复呈现

**ID：TC-01a07543-5a88-76be-8e60-6877c941eaa7**

- 需求位置：R-02、R-03、R-04、R-05；来源 B、C、D。
- 前提：存在原生分页、继续滚动加载、延迟补入媒体或复用可见结果区域的样本。
- 输入/步骤：使用原生滚动或分页加载后续结果；覆盖先显示文字/占位再补入媒体的过程；滚走后返回已见结果；继续加载多批内容。
- 期望：每批新增或更新结果都满足媒体收起、文字及入口保留、预览暂停无声；已处理结果重新呈现后仍满足这些要求。
- 判据：不能只处理首屏或首次创建的结果；延迟设置图片来源、替换封面、替换预览或复用结果区域时不能漏处理；重复处理不能重复删减文字或损坏入口。

### S-06：站内搜索变更及搜索历史导航

**ID：TC-01a07543-5a89-740d-9cb0-9ab1094befb9**

- 需求位置：R-01、R-02、R-03、R-04、R-05；来源 B、C、D。
- 前提：为当前站点准备两个能返回不同媒体结果的搜索词 Q1、Q2。
- 输入/步骤：搜索 Q1；在站内改为 Q2；使用站点原有结果类别、筛选或排序入口更新结果；使用浏览器前进/后退恢复先前搜索；另覆盖直接加载搜索地址。
- 期望：每次搜索结果变化后，当前结果中的媒体收起且预览暂停无声，当前文字和真实入口正常。
- 判据：不能依赖整页刷新才能生效，不能因地址或结果区域变化而漏掉新结果；旧结果的处理不能污染新结果的文字、入口或目标。

### S-07：纯文字和无结果页面

**ID：TC-01a07543-5a8a-7c5a-aa3b-1333dd4bcb91**

- 需求位置：R-03、R-05、R-07；来源 B、D。
- 前提：具有纯文字结果、无结果状态和正常媒体结果的可复现输入或页面状态。
- 输入/步骤：依次进入纯文字结果、无结果状态，再执行能产生媒体结果的搜索。
- 期望：纯文字结果、无结果提示及其原有操作正常；没有可收起媒体时不删减内容，也不主动获取其他结果填充页面；随后出现媒体结果时正常生效。
- 判据：不能把整个搜索容器隐藏、将原生无结果提示误判为待移除内容，或在空结果后停止后续处理。站点本身原有的提示和推荐行为以原生对照为准。

### S-08：主动进入详情页或新标签后正常观看

**ID：TC-01a07543-5a8b-796f-be91-2abcc54f9e8e**

- 需求位置：R-03、R-06、R-08；来源 B、C、D。
- 前提：结果媒体已收起，结果有通向可正常观看详情的真实入口。
- 输入/步骤：主动打开详情页；分别覆盖站点原有的当前页导航和新标签打开方式；查看图片/封面，并按站点原有方式播放有声内容。
- 期望：详情媒体正常显示；用户可正常观看和收听；功能不要求用户增加一次“显示媒体”操作。新标签打开时，原搜索页结果仍保持收起及预览暂停。
- 判据：结果页上的隐藏、尺寸收起、暂停或静音效果不能延续到详情媒体；正常观看以同内容的原生详情对照为准。

### S-09：详情弹窗与背景搜索结果隔离

**ID：TC-01a07543-5a8c-7d24-8322-79a51f49a6bc**

- 需求位置：R-02、R-04、R-05、R-06、R-08；来源 C、D。
- 前提：站点支持从搜索结果主动打开详情弹窗，弹窗打开后背景搜索结果仍在页面中。
- 输入/步骤：打开详情弹窗，查看并播放详情媒体；观察仍可见的背景结果；覆盖弹窗内容延迟载入和背景结果被原生页面更新的情况。
- 期望：弹窗详情正常显示、允许播放和收听；背景结果图片与预览区域仍收起，背景自动预览不播放且无声。
- 判据：不能因弹窗出现而解除全部背景屏蔽，也不能继续把弹窗媒体当作结果预览暂停或隐藏。弹窗播放时允许有来自详情的声音，必须区分详情音轨与背景预览音轨。

### S-10：关闭详情或返回搜索后继续生效

**ID：TC-01a07543-5a8d-7139-9902-83790c4f8d9c**

- 需求位置：R-02、R-03、R-04、R-05、R-06；来源 B、C、D。
- 前提：已从搜索结果进入并观看详情，分别准备详情弹窗及详情页面的适用样本。
- 输入/步骤：关闭详情弹窗；从详情页使用浏览器后退返回搜索；覆盖浏览器恢复旧页面和重新载入结果两种路径；再次悬停结果并继续滚动或搜索。
- 期望：回到搜索环境后，结果媒体仍收起，预览不播放且无声，文字和入口可用；随后加载的新结果继续生效；再次打开详情仍可正常观看。
- 判据：不能因为详情曾被允许播放而使结果卡片恢复预览，也不能因返回时复用页面而遗漏处理；重复打开、关闭、返回不能破坏两种环境的隔离。

### S-11：结果范围以外的媒体保持原生行为

**ID：TC-01a07543-5a8e-77e3-aea9-9eae8e471cbf**

- 需求位置：R-02、R-06、R-08；来源 C、D。
- 前提：准备结果卡片内头像，以及明确位于结果外的页面标识或账户区域图片；准备同站非搜索页面作为对照。
- 输入/步骤：观察搜索页内外的媒体；从搜索进入同站非搜索页面；再返回搜索。
- 期望：结果卡片头像与图片收起；明确位于结果范围以外的图片和非搜索页面媒体维持原生显示与可用性；返回搜索后结果规则继续生效。
- 判据：不能用全站或全页隐藏所有图片/播放器的方法通过结果隐藏测试；不能把结果内作者头像误当成结果外账户区域图片。边界不明确的模块先补充权威归属，不从实现选择器推断。

### S-12：局部处理不主动补结果请求

**ID：TC-01a07543-5a8f-72ba-b31c-1a8eaa43e99b**

- 需求位置：R-05、R-07；来源 D。
- 前提：具有同一批结果、原生加载条件与请求记录的可复现对照；能够区分原生页面请求与为补足结果而增加的动作。
- 输入/步骤：载入结果并保持静置，观察媒体收起；反复呈现或更新同一批已有结果；随后由用户进行一次原生滚动、分页或新搜索，并观察新增结果处理。
- 期望：媒体处理使用已有页面内容，不为填满收起后的空间主动搜索、翻页、模拟滚动或请求另一批结果；用户发起的原生加载仍正常，加载后的媒体规则生效。
- 判据：结合请求记录和动作触发来源，排除原生页面固有请求；出现为填补收起区域而新增的获取结果请求或补结果动作即不满足预期。仅使用站点已有网络接口来补结果也不满足要求。这里不要求取消站点原有图片下载，也不把正常原生加载一律判为违规。

### S-13：媒体能力与 UA 开关及刷新行为隔离

**ID：TC-01a07546-cca1-7540-8346-f6107840ac94**

### S-19：真实扩展重载后旧标签继续响应媒体设置

**ID：TC-01a075d4-7247-7610-8711-52d5eb4d3283**

- 需求位置：R-01～R-09、R-11～R-13；来源 B～G；当前主会话用户反馈“重启浏览器/插件组合后又无效”及主任务确认的旧标签设置同步边界。本用例检验既有行为跨扩展重载是否持续有效，不把该边界认定为用户反馈的唯一原因。
- 前提：使用真实安装且可重载的扩展，同一浏览器配置和扩展身份贯穿测试；四站分别作为目标站。准备旧搜索标签、同站正在播放的详情页或详情弹窗，以及另一站的搜索对照标签；记录原生媒体布局、文字、入口、UA 配置、用户页面文档身份/导航记录和详情播放状态。至少覆盖 UA 相关开关均关闭而媒体开启的组合。
- 输入/步骤：执行以下两组序列；每次重载均通过浏览器扩展管理页的真实重载操作或扩展上下文中的真实 `chrome.runtime.reload()` 完成，确认扩展重新可用后重新打开 options 页操作。旧搜索页、详情页及弹窗全程保留，不手动刷新或以新页面替换；不得用自定义事件、直接重跑内容脚本或模拟存储回调替代真实重载。

| 序列 | 操作与观察点 |
| --- | --- |
| A：`true → 重载 → false → true` | 先开启目标站并建立已收起媒体的旧搜索标签，开始详情播放；真实重载扩展。确认开启选择保留，在旧标签原生加载一批新结果；从恢复后的 options 页关闭目标站，再重新开启。重载后及每次切换后，都检查旧标签已有结果、由原生操作新加载的动态结果，并新开同站搜索标签作当前状态对照。 |
| B：`false → 重载 → true` | 先关闭目标站，再建立显示原生媒体的旧搜索标签，开始详情播放；真实重载扩展。确认关闭选择保留，在旧标签加载动态结果；从恢复后的 options 页开启目标站。重载后及开启后，分别检查旧标签已有结果、动态结果和新开的同站搜索对照标签。 |

- 期望：每个观察点的旧标签、新标签及动态结果均遵循已保存的同一站点选择。`false` 时恢复图片、封面、头像及原生布局和预览能力；`true` 时隐藏并收起媒体、暂停预览且无声。关闭期间出现的结果在重新开启后也被处理；文字和真实入口持续保留。另一站维持自身选择，UA 配置不变；详情持续按原生方式显示和播放，不因重载恢复或设置变化而刷新、中断、额外暂停、静音或重置进度。扩展不得通过重新加载用户页面或额外请求结果来恢复作用。
- 判据：分别核验真实扩展重载已发生、设置已生效、旧标签文档未被替换，以及各状态下的可见性、浏览器布局矩形、预览播放与音轨。旧标签仍保留重载前的隐藏样式不能证明重载后仍在工作，必须通过相反设置和新动态结果验证；设置已为 `false` 且新标签正常、旧标签仍隐藏，或从 `false` 重载后设为 `true` 只对新标签生效，均不满足预期。原生加载请求与扩展主动补结果请求分别归因，详情播放以重载及切换前后的连续观察和原生对照判定。
- 执行错误与行为证据：分别记录重载操作、扩展恢复、设置保存及页面行为的证据。重载调用导致旧扩展执行上下文销毁或控制连接断开时，先确认真实重载和新扩展上下文是否恢复，再判断页面行为；不能将该断连直接等同于产品行为失败，也不能忽略后续观察而判为通过。若重载未完成或控制链路使观察无法继续，应报告具体执行错误和未验证项；只有完成真实重载并取得设置与页面状态后，才能据上述判据作行为结论。
